## ✨ Nicht noch ein Kalorienzähler.

Du möchtest bewusster essen, kennst aber weder die Kalorien jeder Verpackung noch möchtest du täglich eine endlose Produktliste durchsuchen?

**Down Kilos denkt vom Essen aus – nicht vom Produktregal.**

Die Idee: Wähle Gerichte für **Frühstück, Mittagessen und Abendessen**, plane deine Woche und sieh, welche Lebensmittel du dafür einkaufen musst. Die App verbindet persönliche Kalorienziele mit einem **Wochenbudget in Euro** und einer **Einkaufsliste mit echten Produktinformationen**, soweit entsprechende Daten verfügbar und geprüft sind.

> **Du wählst die Mahlzeiten. Down Kilos hilft beim Planen, Rechnen und Einkaufen.**

### So soll sich Down Kilos anfühlen

**1. Profil einrichten.** Ziel, persönliche Angaben, bevorzugten Supermarkt, Budget und Ernährungspräferenzen hinterlegen – ohne verpflichtendes Login.

**2. Woche planen.** Frühstück, Mittagessen und Abendessen auswählen, Mahlzeiten austauschen oder an mehreren Tagen wiederholen.

**3. Einkauf zusammenstellen.** Zutatenmengen über die gesamte Woche addieren und auf tatsächlich benötigte Verkaufsverpackungen umrechnen.

**4. Alltag begleiten.** Das Dashboard zeigt die passende geplante Mahlzeit. Erst mit **„Schon gegessen“** oder einem individuellen Tagebucheintrag werden Kalorien als verzehrt erfasst.

**5. Fortschritt verstehen.** Tageskalorien, Gewichtsentwicklung und Einkaufsbudget bleiben übersichtlich und getrennt.

## 💚 Was Down Kilos besonders macht

### 🗓️ Mahlzeiten statt endloser Produktsuche

Ein Wochenplan stellt die Frage in den Mittelpunkt, die im Alltag wirklich zählt: **„Was esse ich heute?“** Geplant sind eine Tagesansicht mit passenden Rezepten, wiederverwendbare Lieblingsgerichte sowie eine Wochenübersicht von Montag bis Sonntag.

### 🛒 Eine Einkaufsliste, die in Packungen denkt

Siebenmal Porridge bedeutet nicht sieben Packungen Haferflocken.

**Beispielrechnung:**

- 60 g Haferflocken je Frühstück
- 7 Frühstücke = 420 g Gesamtbedarf
- Bei einer passenden 500-g-Packung: **1 Packung** auf der Einkaufsliste
- Rechnerischer Rest: **80 g**

Die Packungsberechnung soll auch verschiedene Mahlzeiten miteinander verbinden, statt gemeinsame Zutaten mehrfach einzukaufen. Das Beispiel illustriert die Berechnungslogik und ist **kein behaupteter Netto-Produktdatensatz**.

### 🔥 Kalorien verständlich machen

Der Produktkatalog unterscheidet zwischen:

| Ansicht | Bedeutung |
| --- | --- |
| **Je 100 g / 100 ml** | Nährwertbezugsgröße des konkreten Lebensmittels |
| **Je Stück / Portion** | Etwa 1 Scheibe Toast, 1 Ei oder 250 ml Milch – nur mit belastbarer Mengenbasis |
| **Ganze Packung** | Energie der vollständigen, entsprechend gekennzeichneten essbaren Verkaufsmenge |

**Geplante**, **gekaufte** und **tatsächlich gegessene** Kalorien sind drei verschiedene Werte. Down Kilos soll sie niemals miteinander verwechseln.

### 🥦 Ernährung, die zu Menschen passt

Die geplante Rezeptauswahl berücksichtigt persönliche Ernährungsformen, Unverträglichkeiten, Allergien und individuell ausgeschlossene Zutaten. Sicherheitskritische Allergenprüfungen müssen auf nachvollziehbaren Zutaten- und Produktinformationen beruhen – nicht allein auf einer KI-Vermutung.

### 🏪 Supermarktbezug statt Fantasiepreise

Der erste Schwerpunkt ist **Netto Marken-Discount**. Langfristig sollen weitere Händler unterstützt werden.

Produkte, Bilder, Nährwerte und Preise müssen aus nachvollziehbaren Quellen stammen. **Ein allgemeines Lebensmittel in einer offenen Datenbank ist nicht automatisch als aktuell bei Netto erhältlich bestätigt.** Wenn ein Preis fehlt oder veraltet ist, muss die App das offen zeigen.

### 📷 Scannen und 🤖 KI-Assistenz – Perspektive

Ein Barcode-Scanner und ein persönlicher KI-Ernährungsassistent gehören zur Produktvision. Die KI soll bei Mahlzeitenideen helfen und auf überprüfbare Produktdaten zugreifen; Nährwertrechnung, Allergenkonflikte und Preisberechnung bleiben regelbasiert überprüfbar. Diese Funktionen sind **nicht pauschal als bereits fertiggestellt ausgewiesen**.

## 🧩 Technik

Der **aktuell überprüfte Repository-Stand** nutzt folgenden Web-Stack:

| Baustein | Technologie |
| --- | --- |
| Frontend | Angular **21** (Standalone Components) |
| Sprache | TypeScript **5.9** |
| Styling | SCSS und Tailwind CSS **3** |
| Routing | Angular Router |
| Reaktive Daten | Angular Signals und RxJS |
| Forms | Angular Forms |
| Icons | Lucide Angular |
| Tests | Vitest über Angular-Test-Builder |
| Build | Angular CLI / `@angular/build` |

**Android:** Eine Veröffentlichung über Google Play ist geplant. Im überprüften `package.json` ist noch keine Capacitor-Abhängigkeit aufgeführt. Daher wird ein fertiger nativer Android-Build hier **nicht als bestätigt** dargestellt.

**Backend-Grundsatz:** Falls eine zentrale API für Rezepte, Produktimports oder spätere KI-Funktionen erforderlich wird, ist **Python + Django + Django REST Framework + PostgreSQL** die vorgesehene Architektur. Diese Entscheidung ist eine Zielarchitektur und keine Behauptung über einen bereits laufenden Server.

### Datenquellen als langfristige Grundlage

- [Open Food Facts](https://world.openfoodfacts.org/) – Lebensmittelkennungen, Produktangaben und Nährwerte unter Beachtung der Daten- und Bildlizenzen.
- [Open Prices](https://prices.openfoodfacts.org/) – datierte Preisbeobachtungen, soweit verfügbar.
- Autorisierte Händler- und Produktfeeds – nur nach Prüfung von Zugang, Lizenz und tatsächlicher Händlerzuordnung.
- Eigene, geprüfte Rezepte – mit konkreten Zutatenmengen, Zubereitung und nachvollziehbarer Nährwertbasis.

**Keine erfundenen Produkte. Keine erfundenen Supermarktpreise. Keine als sicher ausgegebenen ungeprüften Allergieinformationen.**

## 🚀 Lokal starten

### Voraussetzungen

- Aktuelle **Node.js-LTS-Version**, kompatibel mit der verwendeten Angular-21-Version
- **npm** (im Repository ist `npm@11.6.2` als Paketmanager deklariert)
- Git

### Installation

```bash
# Repository klonen
git clone https://github.com/marioramirez90/downkilos.git
cd downkilos

# Abhängigkeiten aus dem Lockfile installieren
npm ci

# Entwicklungsserver starten
npm start
```

Öffne anschließend die vom Angular-Entwicklungsserver angezeigte lokale Adresse (standardmäßig `http://localhost:4200`).

### Nützliche Befehle

```bash
npm start          # Entwicklungsserver
npm run build      # Produktions-Build
npm run build:prod # Build mit Basis-Pfad /projekte/down-kilos/
npm test           # Vorhandene Tests
```

`build:prod` verwendet einen **projektspezifischen Base-Href** für die bestehende Website. Für eine Android-WebView oder einen anderen Hosting-Pfad muss die Build-Konfiguration passend überprüft werden.

> Hinweis: Diese Befehle stammen aus der aktuell eingesehenen `package.json`. Ein erfolgreicher Lauf wurde für diese README nicht behauptet.

## 🔐 Datenschutz & Vertrauen

Down Kilos ist für einen **Gastmodus ohne verpflichtendes Benutzerkonto** konzipiert. Ernährungs- und Gewichtsdaten sind sensibel. Deshalb gelten für Entwicklung und Veröffentlichung folgende Grundsätze:

- Persönliche Angaben nur erfassen, wenn sie für die Funktionen erforderlich sind.
- Tatsächliche Speicherorte und Netzwerkübertragungen dokumentieren.
- Kein Versand sensibler Daten in unnötige Logs oder Analysedienste.
- Lokale Datenlöschung zuverlässig ermöglichen.
- Externe Datenquellen und deren Nutzungsrechte transparent behandeln.
- Datenschutz- und Google-Play-Datensicherheitsangaben vor Veröffentlichung anhand der wirklichen Implementierung prüfen.

Die bloße Nutzung lokaler Speicherung bedeutet **nicht automatisch**, dass die App überhaupt keine Daten an Dritte überträgt: externe Produktabfragen und eingebundene SDKs müssen gesondert bewertet werden.

### Gesundheitlicher Hinweis

Down Kilos unterstützt die allgemeine Ernährungs- und Einkaufsplanung. Berechnete Kalorienbedarfe sind **Schätzwerte**. Die App ist kein Medizinprodukt, stellt keine Diagnosen und ersetzt keine medizinische Beratung. Es gibt keine garantierten Abnehmerfolge.
